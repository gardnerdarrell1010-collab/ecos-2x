# ADR-001 — PostgreSQL is the ECOS 2.x operational system of record

**Status:** Accepted Phase 0 design; operational maturity DESIGNED.

**Context:** The review found overloaded spreadsheet Tasks and repeated executor-local
persistence failures. Obligations, approvals, claims and audit need transactional integrity.

**Decision:** One PostgreSQL modular monolith owns operational state after separately approved
cutover. Governed operations atomically change typed state, events and outbox. 1.x remains
authority until that cutover; this repository has no operational authority.

**Rationale:** Constraints and transactions enforce invariants independently of agent memory.

**Alternatives considered:** Spreadsheet continuation; per-worker databases; agent-session state.
They cannot provide the required single transactional authority without added coordination.

**Consequences:** Phase 1 must implement migrations, roles, constraints and operation procedures;
external calls happen after commit. Database availability/recovery is a first-class concern.

**Portability impact:** Canonical PostgreSQL SQL and ordinary drivers, with no hosted-only data model.

**Acceptance implications:** Clean install/restore, atomic mutation/audit/outbox and API readback;
API-03, MIG-01, REST-01. No production authority is inferred from local test success.
