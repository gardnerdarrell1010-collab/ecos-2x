# ADR-005 — Query-time priority and atomic claims

**Status:** Accepted Phase 0 design; initial ordering policy is versioned, pending operational tuning.

**Context:** Continuous rank rewrites and spreadsheet leases create drift and concurrency hazards.

**Decision:** Compute readiness/eligibility and lexicographic priority at selection time; use
row locking with SKIP LOCKED, one active claim index, monotonic version and expiring fence.
Freeze selection evidence in an immutable execution event. RUN NOW bypasses no safety gate.

**Rationale:** One transaction selects and owns work, avoiding separate read/update races.

**Alternatives considered:** Persist Dispatch Rank; optimistic read-then-write ownership; long
cross-surface leases. Each loses needed freshness or failure isolation.

**Consequences:** Expired claims must be closed explicitly, gates rechecked under lock and stale
completions rejected. No clock-dependent partial-index predicate. See claim_work.md.

**Portability impact:** Standard PostgreSQL locking plus ordinary UUID/time/version fields.

**Acceptance implications:** C-01..C-07; real 100-connection contention remains pending Phase 1.
The executable oracle rejects multiple winners and stranded/invalid ownership evidence.
