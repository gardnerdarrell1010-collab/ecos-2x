# ADR-013 — External artifacts remain provider-authoritative where applicable

**Status:** Accepted Phase 0 design.

**Context:** Drive bytes, Gmail transport, Toast transactions and provider permissions are facts
at external authority boundaries, not database fields ECOS may invent.

**Decision:** Store stable provider IDs/revisions, URIs, hashes, sizes, timestamps and provenance;
keep business interpretation/obligations in ECOS. Reconcile provider evidence before claiming effect.

**Rationale:** Distinguishing observation from authority prevents fabricated delivery/file success.

**Alternatives considered:** Copy provider status without evidence; make ECOS a second provider master;
store only fragile URL links. These lose verifiability or authority clarity.

**Consequences:** Readback/hash checks, explicit unknowns, provider-specific policies and artifact
availability inventory during export. Financial totals must retain as-of/source identity.

**Portability impact:** Provider-boundary registry defines adapters and replacement expectations.

**Acceptance implications:** Exact-byte file verification, stable reference migration, provider-success
reconciliation and dashboard unknown-state preservation; EV-02 and SHADOW-01.
