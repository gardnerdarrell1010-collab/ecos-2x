# ADR-016 — Evidence-based maturity

**Status:** Accepted Phase 0 design.

**Context:** Prior integrity reports asserted success while end-to-end chains remained blocked.

**Decision:** Use DESIGNED -> BUILT -> END-TO-END VERIFIED -> SHADOW VERIFIED -> PRODUCTION
VERIFIED, represented by lowercase machine values. Each advancement requires scoped immutable
evidence and an authorized reviewer. Operational maturity here remains DESIGNED.

**Rationale:** Implemented files, synthetic tests and actual production behavior are different claims.

**Alternatives considered:** Binary done flag; executor self-report; treating mocks as E2E. These
hide untested boundaries and retirement risk.

**Consequences:** Report pending integration gates explicitly; release gate fails on skips. No 1.x
worker retirement before replacement Production Verified, except explicitly retired capabilities
after current-authority confirmation. A005 additionally requires two restore cycles.

**Portability impact:** Maturity/evidence are ordinary governed data independent of tools or dashboards.

**Acceptance implications:** Catalog tracks gate phase/status; Phase 1 manifest maps deliverables.
No passing offline test may silently promote operational maturity or authorize production effects.
