# ADR-008 — Semantic proposal to deterministic commit boundary

**Status:** Accepted Phase 0 design.

**Context:** Interpretation is necessary but must not grant arbitrary table mutation authority.

**Decision:** Semantic stages produce immutable versioned proposals with sources, expected
versions, governed operations, evidence, ambiguity and hash. Deterministic operations validate
and commit independent items atomically. A023/A053/A054 demonstrates the generic pattern.

**Rationale:** Durable proposals permit review/restart without repeated reinterpretation and
optimistic conflicts isolate stale source assumptions.

**Alternatives considered:** Direct agent SQL; one all-or-nothing untyped batch; reparsing on every
restart. These lose governance, sibling isolation or evidence stability.

**Consequences:** Allowlist/versioned schemas, per-item dependency DAG/checkpoints and auth checks.
Invalid envelope rejects batch; independent valid siblings can survive invalid/stale items.

**Portability impact:** Any semantic engine can produce the same contract; no ChatGPT session required.

**Acceptance implications:** SEM-01/SEM-02 invalid/stale/conflicting siblings, hash mutation,
restart reuse and no direct Task mutation; API-01 authorization remains deterministic.
