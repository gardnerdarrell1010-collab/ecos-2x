# ADR-015 — Typed quarantine migration from ECOS 1.x

**Status:** Accepted Phase 0 design.

**Context:** Review found duplicate IDs, column drift, overloaded Tasks, uncontrolled status prose
and noisy Run Control history. Direct normalized imports would institutionalize these defects.

**Decision:** Immutable raw batch -> typed quarantine -> validation -> identity reconciliation ->
versioned transformation -> governed promotion. Every authoritative family has a disposition.

**Rationale:** Source-row identity and explicit error classification preserve evidence without
granting malformed legacy data operational authority.

**Alternatives considered:** Direct COPY into final tables; choose first duplicate; normalize statuses
by fuzzy text matching. These silently discard or misinterpret authoritative source evidence.

**Consequences:** Preserve batch/locator/hash and all collisions, explicit mapping decisions and
promotion idempotency. Rebuild runtime state; archive noisy history outside hot tables/Git.

**Portability impact:** Standard extraction manifests, schemas and mapping registries, not sheet UI logic.

**Acceptance implications:** MIG-02 zero unclassified errors, count/hash/business-total reconciliation,
duplicate/drift negative fixtures and replay-safe promotion before later cutover.
