# ADR-009 — Execution surfaces and capability routing

**Status:** Accepted Phase 0 design.

**Context:** Fifty-five worker records preserve business functions but are not service boundaries.

**Decision:** Data-driven executor/instance/capability/requirement records route stages to
DATABASE_DETERMINISTIC, RESIDENT_DETERMINISTIC_PROVIDER, ONLINE_SEMANTIC or INTERACTIVE_ADA.
HYBRID means a staged DAG; availability uses expiring server-received evidence.

**Rationale:** Shared engines can preserve controls while avoiding a service per legacy worker.

**Alternatives considered:** Hard-coded worker dispatch; platform-specific universal capabilities;
one lease for a hybrid job. They impede substitution and recovery.

**Consequences:** Boot identity and capability attestation matter; incompatible pairs are excluded
locally without globally blocking work. Human actions use the same governed operations.

**Portability impact:** Semantic capability names describe function, not an AI product.

**Acceptance implications:** C-04 pair isolation, stage handoff and PORT-01 platform substitution;
registry coverage tests prove 55 records without importing them into runtime dispatch.
