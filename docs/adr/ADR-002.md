# ADR-002 — Supabase is the initial host, not the architecture

**Status:** Accepted Phase 0 design; region/tier/cost OWNER-01 unresolved.

**Context:** A managed initial host is selected, while the system must survive host substitution.

**Decision:** Isolate Supabase configuration and operational runbooks under config/hosts.
Core correctness cannot require Realtime, Edge Functions, hosted Auth or webhooks.

**Rationale:** Durable PostgreSQL state and portable operations are sufficient to describe ECOS.

**Alternatives considered:** Host-native functions/queues as sole authority; self-host first.
The former adds lock-in; the latter is not the approved initial hosting direction.

**Consequences:** Explicit replacements and independent backups must be maintained. Provisioning
is outside Phase 0; hosting settings cannot be invented to resolve owner choices.

**Portability impact:** Restore standard PostgreSQL and use conventional API/executor runtimes.

**Acceptance implications:** REST-01 on a clean different host without access to the original
Supabase project. Static checks reject hosted SDK imports from the portable core.
