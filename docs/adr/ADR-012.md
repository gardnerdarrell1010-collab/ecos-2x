# ADR-012 — AI-platform and PostgreSQL-host portability

**Status:** Accepted Phase 0 design.

**Context:** A future engineer/AI must understand ECOS without this conversation or original host.

**Decision:** Source-controlled SQL, OpenAPI, JSON Schema, ADRs, runbooks and ordinary tests are
canonical. APIs and bootstrap packages carry governed context; providers/platforms are adapters.

**Rationale:** Explicit contracts enable conformance and controlled substitution.

**Alternatives considered:** Product-only prompts/config; proprietary queue/functions as architecture.
These do not independently describe state transitions and recovery.

**Consequences:** Version contracts, pin dependencies, keep secrets/sensitive exports out of Git,
and retain reproducible fixtures and pending live gates. Local paths are historical metadata only.

**Portability impact:** No Supabase or AI SDK imports in core; no Windows runtime path dependency.

**Acceptance implications:** Offline validation on ordinary Python, standard PostgreSQL restore,
replacement semantic engine with package-only context; REST-01 and PORT-01 remain live gates.
