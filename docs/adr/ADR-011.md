# ADR-011 — Database backup, semantic continuity and portable export are distinct

**Status:** Accepted Phase 0 design; RPO/RTO/retention OWNER-02/05 unresolved.

**Context:** Semantic snapshots cannot restore database invariants; hosted backups alone may not
survive account/host loss or provide a portable system reconstruction.

**Decision:** Separate managed backup/PITR, independent logical PostgreSQL backup, portable ECOS
export and restore verification. Maintain AI Memory as a separate continuity subsystem.

**Rationale:** Each failure domain requires different evidence and reconstruction mechanisms.

**Alternatives considered:** Sheet-copy backup port; rely only on PITR; continuity text as backup.
None reconstructs the complete portable operational system independently.

**Consequences:** Darrell-controlled encrypted copies, checksummed manifests, sanitized role/secret
references, tested restore instructions and measured recovery objectives. No plaintext secrets.

**Portability impact:** A complete package reconstructs on standard PostgreSQL with artifact coverage
limitations made explicit. External provider authority is not magically copied by a DB dump.

**Acceptance implications:** REST-01 corruption/clean restore; A005 retirement needs two successful
cycles plus production verification. Proposed recovery numbers remain unapproved targets.
