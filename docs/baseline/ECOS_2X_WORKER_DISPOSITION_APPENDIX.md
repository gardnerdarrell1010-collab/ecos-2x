# ECOS 2.x Worker-by-Worker Disposition

This appendix covers all 55 live Task Loop records fresh-read on 2026-09-28. “Inputs/outputs” summarize the authoritative live contract; proposed objects are implementation targets, not existing schema. Every retained process uses `execution_run`, `execution_event`, claims/fences, correlation IDs, and audited operation calls.

## Acceptance maturity scale

- **E2E:** built and end-to-end verified in isolation.
- **Shadow:** correct against live 1.x outcomes without authority.
- **Production:** authoritative, monitored, restore-tested, and rollback-proven.
- No 1.x worker retires before the replacement is Production verified unless the business capability itself is explicitly retired.

## Consolidated future runtime inventory

The 55 workers reduce to a much smaller set of execution mechanisms:

1. PostgreSQL invariant/transition procedures.
2. PostgreSQL scheduler/readiness/claim/recovery functions.
3. One generic deterministic dispatcher.
4. One generic semantic executor interface.
5. Gmail adapter.
6. Drive/Docs adapter.
7. Twilio/communications adapter.
8. Toast adapter.
9. Finance adapter.
10. Calendar adapter.
11. Vercel publisher adapter.
12. Resident renderer/materializer.
13. Backup/export/restore operator.
14. Independent watchdog and external uptime monitor.

Worker IDs remain traceable migration aliases in `legacy_identity`, but do not dictate future process boundaries.

## Subordinate-function preservation

- A023/A053/A054 remain three explicit stages—receipt/package, semantic proposal, deterministic commit/ACK—even if implemented by shared generic engines.
- A026 retains independent source availability semantics: one missing source degrades the assembled dashboard but does not erase other sections.
- A029 acquisition, SQL feature calculation, A020/A021 forecasting, and A019 feedback remain separate lifecycle stages with independently testable evidence.
- A022 status derivations consolidate into database views, while A044 remains a distinct materialization boundary.
- A010/A027/A028 consolidate queue machinery, not channel-specific provider evidence or policies.
- Finite A017/A030 history is preserved without permanent workers.
